# River scene source research — 28 October 2026

Scope: research and read-only diagnosis for Potomac 01646500 and Columbia 14105700. No scene implementation changes in this research pass.

## Verified current behavior

- The river pages use embedded BAKED_BUILDINGS rather than a runtime building API. Potomac contains 2,300 footprint entries; Columbia contains 2,192. Neither contains height or building:levels tags. The renderer therefore uses its default 7 m height for these entries.
- Buildings are loaded only after overview elevation, overview imagery, detail elevation and detail imagery complete. Desktop detail imagery requests 256 tiles. A separate temporary Chrome run of Columbia reached 2,144 rendered buildings by about 20 seconds, from zero at 10 seconds. That run showed no failing map API requests and no JavaScript exceptions. A missing optional data/pulls/manifest.json and favicon returned 404, unrelated to building geometry.
- Imagery is Esri World Imagery, and terrain is AWS Terrarium. The source is draped onto fixed-resolution meshes; new imagery alone cannot provide textured 3D facades or fix river shape.
- The river API supplies NLDI/NHDPlus V2 centerlines. The rendered water is generated by a connected-cell terrain flood fill, with a ribbon farther away. It is not clipped to authoritative bank polygons. Water elevation uses an assumed baseline tied to the record's 25th-percentile discharge, rather than a verified acquisition-time river level and shared vertical datum.
- Missing DEM tiles can remain transparent/black in the mosaic and be decoded as invalid low elevations. This is a code-path risk found in inspection; it was not observed as a network failure in the Columbia diagnostic run. Do not call it the confirmed cause of every visual artifact.

## Candidate sources

### USGS 3DHP Waterbody polygons and Flowline
https://3dhp.nationalmap.gov/arcgis/rest/services/usgs_3dhp_all/FeatureServer
https://www.usgs.gov/3d-hydrography-program/access-3dhp-data-products
Waterbody layer 60 supplies mapped polygon footprints; flowline layer 50 supplies network lines. A bbox query near Columbia returns Lake Bonneville's polygon, representing the reservoir reach through The Dalles. A bbox query near Potomac returns River polygons. Both local results currently have workunitid=NHD, so they are legacy hydrography carried through the current service, not confirmed newly lidar-derived bank mapping. Inspect source dates and compare against aerial imagery before adopting. Preserve polygon holes/islands. Mapped footprints do not establish historical-date inundation.

### USGS 3DEP detailed terrain / TNM Access API
https://www.usgs.gov/3d-elevation-program/about-3dep-products-services
https://tnmaccess.nationalmap.gov/api/v1/docs
Queried dataset Digital Elevation Model (DEM) 1 meter with local bounding boxes. Columbia bbox (-121.22,45.58,-121.16,45.64) intersects two catalog products from WA_FEMAHQ_2018_D18. Potomac bbox (-77.16,38.92,-77.10,38.98) intersects six products, including VA_NorthernVA_B22 and MD_Central_Processing_D24. Intersection is verified, not complete per-pixel coverage of the study area. Check bounds, native resolution, acquisition dates and vertical references. Crop to the study reach and render with multiple detail levels. Bare-earth terrain does not supply riverbed bathymetry.

### USGS NAIP Plus imagery
https://imagery.nationalmap.gov/arcgis/rest/services/USGSNAIPPlus/ImageServer
Official service describes imagery resolution from six inches to 1 m, varying by source/location. It exposes acquisition_date and resolution metadata. Compare the actual local imagery against existing Esri imagery before promising a resolution improvement. These are captured aerial photographs, not live or date-slider-matched images.

### Overture buildings
https://docs.overturemaps.org/guides/buildings/
https://docs.overturemaps.org/schema/reference/buildings/building/
https://docs.overturemaps.org/getting-data/overturemaps-py/
Open building footprints, optional building parts, optional heights/floor counts and property-level source metadata. Query/crop the two areas from GeoParquet using the supported bounding-box download client and serve compact local geometry. It is a downloadable dataset, not a guaranteed browser-ready live building API. Check local height completeness; do not imply every building has a measured height or textured facade. Missing heights must remain explicitly estimated. Preserve source attribution/licenses.

### Google Photorealistic 3D Tiles
https://developers.google.com/maps/documentation/tile/3d-tiles-overview
https://developers.google.com/maps/documentation/tile/usage-and-billing
https://developers.google.com/maps/documentation/javascript/3d/coverage
https://developers.google.com/maps/documentation/tile/policies
Strong visual option: captured textured 3D geography. Requires an API key and billing-enabled project. Local 3D surface coverage at these two specific reaches has NOT been confirmed. Respect attribution and cache/offline restrictions. Captured mesh water is not a dynamic hydraulic model and may complicate an animated river overlay.

### Rendering support
https://github.com/NASA-AMMOS/3DTilesRendererJS
Open-source 3D Tiles rendering support for Three.js offers a route to integrating streamed 3D data with the existing app. It supplies rendering, not geographic content or API credentials. Verify version compatibility and XR performance during any later prototype.

## Recommended direction

Start with the open-data route in the existing Three.js/WebXR app: independent progressive loading with proper missing-tile handling; mapped water polygons with island holes; a clipped higher-resolution terrain and imagery area; better attributed building footprints and available heights. Distinguish imagery dates and measured/estimated metadata. Assess Google photorealistic coverage as an optional visual route if a billing-enabled key is acceptable. No paid resources were created or used during this research.

A stronger digital twin also needs a consistent water-level/terrain vertical reference, measured stage where available, river channel/bathymetry information, and hydraulic validation for claimed flood extents. Better buildings and photographs alone do not validate the current flood-fill approximation. USACE HEC-RAS documentation describes terrain/channel-based hydraulic modeling: https://www.hec.usace.army.mil/confluence/rasdocs/hgt/latest/tutorials/2d-unsteady-flow/2d-model-development-and-refinement
