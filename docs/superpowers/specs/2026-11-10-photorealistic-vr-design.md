# Potomac photorealistic VR trial

User approved the six-step proposal: retain Three.js/WebXR; check actual imagery coverage, trial Google Photorealistic 3D Tiles through 3DTilesRendererJS, inspect aerial/close views, include one interactive floating data panel, retain independent USGS data, and compare before extending to Columbia. VR is a core requirement. No switch to CesiumJS, native engine, new AWS deployment, bulk map download, or permanent Google-content cache.

Create a new experiment/photorealistic-vr branch from the completed mapped-water branch. Keep current station and data-space pages intact. Build /photorealistic-vr/ as an isolated static page, with a current pinned Three.js build independent of the legacy pages' r160 dependency. Use pinned 3d-tiles-renderer 0.5.4, matching current peer dependencies; self-host required library code/decoders and their licenses so no package manager is required to run the supplied site.

Support direct Google API access or Cesium ion Google asset access. User confirms no account/key exists yet. Never borrow demo credentials, create an account, activate billing, store a credential in Git/URL/browser persistent storage, or claim authenticated geography was verified without access. Provide an in-page password field, explicit connect/disconnect, one persistent tileset while changing data/views, root-start counter, sanitized errors and attribution in desktop and immersive views. Evaluate publicly hosted examples only through their intended public UI; do not extract their keys. The access handoff must be concrete and reviewable after all independent implementation is done.

Use geographic ECEF→local East/Up/South coordinates at the official Potomac gauge. Provide aerial and close inspection views plus a comfortable immersive tabletop default. Root scene geometry is streamed and unmodified; old baked white boxes are not loaded into this scene. One readable world-space canvas data panel is draggable/minimizable and has issue-date/model/lead controls usable by mouse and controller rays. Reuse existing chart3d data and comparison helpers; preserve exact issue/target pairing and distinguish estimated stage from measured data. Do not turn discharge into a physically calibrated water surface on the new mesh.

WebXR session tracking, stereo cameras and controller selection are real rendering paths, with desktop emulation for verification where available. Headset hardware appearance/performance remains unverified. Keep attributions visible when panels are minimized. Limit streamed geometry memory and offer detail settings. Initially focus Potomac; retain Columbia coordinates for the coverage check, without claiming integration complete there.

Success: isolated VR viewer loads; same data controls and camera/view changes do not reconnect tiles; no credentials persist/leak; source failures explain the missing imagery without fake landscape substitutes; an interactive panel works; available public sample geometry and desktop XR emulation validate the rendering path. Actual river tile fidelity is a separately reported result contingent on provider access.
